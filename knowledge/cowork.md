## Teachable knowledge

**Unit 1: Cowork vs. Chat — choosing the right mode**
- Cowork hands off a whole multi-step task (Claude plans, executes, returns a polished deliverable); Chat is a back-and-forth exchange one turn at a time.
- Judge task shape first: research + drafting + formatting across files calls for Cowork; a quick single answer doesn't.
- Setup requires a paid plan (Pro/Max/Team/Enterprise) and desktop app access; no coding needed.
- A first delegated task should be specific enough for Claude to plan around end-to-end, not a fragment needing mid-task clarification.
- HANDS-ON EXERCISE: Take a real multi-step task the user does by hand across two or more files/apps (e.g., a weekly report compiled from several sources), delegate it as one Cowork task, and compare the result to a turn-by-turn chat approach.
- Quiz: Q: What distinguishes Cowork from Chat? A: Cowork plans and executes a multi-step task end-to-end and returns a deliverable; Chat is conversational, one turn at a time. Q: What's required before delegating a task? A: A paid plan and the desktop app set up.

**Unit 2: Standing context — stop re-explaining yourself**
- Global instructions apply across all tasks; project-level context applies within one project's scope.
- Setting context once removes the need to restate preferences, formats, or background in every new task.
- Standing context should hold stable facts (conventions, audience, tone, constraints), not one-off task details.
- HANDS-ON EXERCISE: Check whether the user's workspace has global instructions or project context configured; if not, draft a starter set from a recent task's implicit requirements.
- Quiz: Q: Difference between global instructions and project context? A: Global instructions apply to all tasks; project context is scoped to one project.

**Unit 3: Teaching Cowork — Skills and Plugins**
- Skills teach Cowork an individual's workflow conventions; Plugins encode a team's domain expertise (research routines, document generation, browser automation) into reusable, shareable capabilities.
- Building a plugin from scratch and customizing an existing one are separate, distinct paths.
- Validate a skill/plugin for correctness and safety before relying on it or sharing it — never trust it blindly.
- HANDS-ON EXERCISE: Turn a workflow the user repeats often (e.g., a weekly review) into a Skill or Plugin, then validate it against a real task before sharing it with a teammate.
- Quiz: Q: Practical difference between a Skill and a Plugin? A: A Skill teaches Cowork one person's way of working; a Plugin encodes a team's expertise as a shareable capability. Q: What precedes sharing a skill/plugin with a team? A: Validation for correctness and safety.

**Unit 4: Working across surfaces**
- Claude in Chrome extends Cowork into browser-based research and web actions instead of manual copy-paste between tabs.
- Claude for Microsoft 365 connects Cowork directly to Office document workflows.
- Route tasks through the right integrated surface deliberately, rather than manually shuttling data between tools.
- HANDS-ON EXERCISE: Take a task that currently involves manually copying data from a browser or Office document into Claude, and redo it using the matching integration instead.
- Quiz: Q: Name the two external surfaces Cowork integrates with. A: Claude in Chrome and Claude for Microsoft 365.

**Unit 5: Safety, sharing, and scaling the practice**
- Working safely with an autonomous tool means reviewing what it's about to do to files, browser, or integrations before it acts, not only checking results after.
- Schedule recurring tasks to run on a cadence automatically instead of manually re-delegating each time.
- Share completed workflows (skills, plugins, context setups) with teammates so the work compounds across the team instead of staying single-use.
- Department-appropriate task framing (research-then-brief for sales/marketing, structured question-briefing for legal) beats a vague request.
- Use live artifacts as a structured review surface for deliverables, rather than leaving output buried in chat.
- HANDS-ON EXERCISE: Take a real recurring task, schedule it in Cowork, and route the deliverable into a reviewable artifact/document rather than plain chat output.
- Quiz: Q: Why schedule a recurring task instead of manually re-delegating it? A: It runs automatically on a cadence without repeated manual triggering. Q: Recommended safety practice before an agent acts autonomously? A: Review what it's about to do before it acts, not just the result afterward.
